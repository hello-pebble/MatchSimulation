# Phase 5-2 시작 전 계획 문서 — 채팅 Short Polling (자동 새로고침)

작성일: 2026-08-01
선행 단계: Phase 5-1 (채팅 MVP — 새로고침 + afterId 증분 조회) 완료

## 1. 배경과 목표

1단계 채팅은 사용자가 [새로고침]을 직접 눌러야 상대 메시지를 받는다.
이 불편을 **Short Polling**으로 해소한다: 클라이언트가 **3초 주기**로 서버에
새 메시지를 자동 조회한다 (전통적인 AJAX 방식).

- 서버 API는 **변경 없음** — 5-1에서 고정한 `GET /api/chat/{matchId}/messages?afterId=N`
  계약을 그대로 재사용한다. 새 메시지가 없으면 빈 배열이 반환된다.
- 대신 Short Polling의 구조적 비용(새 메시지가 없어도 반복되는 **빈 요청**)을
  실측으로 기록해, 다음 단계(Long Polling)의 필요성을 데이터로 남긴다.

## 2. 설계

| 구성요소 | 내용 |
| :--- | :--- |
| 서버 | 변경 없음 (afterId 증분 조회 재사용) |
| 콘솔 | [자동 새로고침 시작/중지] 토글 — `setInterval` 3초 주기로 refreshChat() 호출 |
| 폴링 상태 표시 | 폴링 횟수 / 새 메시지 수신 건수 / 빈 응답 횟수를 실시간 카운트 |
| 안전장치 | 대화방 변경·토글 중지 시 `clearInterval`, 중복 시작 방지 |

## 3. 엣지케이스 정의

| # | 케이스 | 기대 동작 |
| :--- | :--- | :--- |
| E1 | 새 메시지 없는 폴링 | 빈 배열 응답, 화면 변화 없음 (빈 응답 카운트 증가) |
| E2 | 상대가 전송 | 다음 폴링(≤3초)에 자동 수신 |
| E3 | 토글 중지 | 폴링 즉시 중단, 재시작 시 afterId 이어서 조회 |
| E4 | 자동 새로고침 중복 시작 | 기존 인터벌 유지(중복 타이머 방지) |
| E5 | 폴링 중 토큰 만료/권한 오류 | 에러 응답 표시 후 폴링 자동 중지 |
